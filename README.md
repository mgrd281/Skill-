# دليل أدوات التصميم والتطوير

دليل عربي منظّم لأفضل مهارات Claude وخوادم MCP والمكتبات والأدوات، مع وصف قصير لكل أداة، ونجوم GitHub، وأمر التثبيت، ورابط المستودع والموقع الرسمي، وأداة "ماذا تبني؟" التي تعرض الأدوات المناسبة لنوع مشروعك.

مبني بـ [Astro](https://astro.build). الصفحات كلها تُولَّد ثابتة وقت البناء، فالموقع سريع ويعمل حتى بدون JavaScript في القراءة.

## الهيكل

```
data/
  tools.json        كل الأدوات (هنا تضيف وتعدّل)
  categories.json   الأقسام وترتيبها
  projects.json     أنواع المشاريع ونصائحها والأدوات المقترحة
  meta.json         تاريخ آخر تحديث للنجوم (يُحدَّث تلقائيًا)
src/
  pages/index.astro         الصفحة الرئيسية
  pages/tools/[slug].astro  صفحة مستقلة لكل أداة
  pages/category/[id].astro صفحة لكل قسم
  pages/search.json.ts      فهرس البحث (ومثله /de/ و/en/)
  lib/search.js             تطبيع البحث وترتيب النتائج و«هل تقصد»
  lib/install.js            حزمة التثبيت وإعداد خوادم MCP لكل برنامج
  scripts/filter.js         البحث والفلترة والترتيب في الرئيسية
  scripts/quick-search.js   البحث السريع في باقي الصفحات
scripts/
  update-stars.mjs  يجلب النجوم وتاريخ آخر تحديث من GitHub
  discover.mjs      يبحث عن أدوات جديدة ويكتب تقريرًا للمراجعة
  check-links.mjs   يفحص كل الروابط ويكتب تقريرًا بالمعطّل والمنقول
  check-data.mjs    يفحص سلامة البيانات
.github/workflows/update-stars.yml  تحديث أسبوعي تلقائي
```

## التشغيل محليًا

يحتاج Node.js 20 أو أحدث.

```bash
npm install
npm run dev        # موقع محلي على http://localhost:4321
npm run check      # فحص البيانات
npm run build      # بناء الموقع في مجلد dist
```

## إضافة أداة جديدة

أضف كائنًا في آخر `data/tools.json`:

```json
{
  "slug": "my-tool",
  "cat": "design",
  "name": "My Tool",
  "kind": "Skill",
  "gh": "https://github.com/owner/repo",
  "site": "https://example.com",
  "stars": null,
  "cmd": "npx skills add owner/repo",
  "use": ["web", "landing"],
  "desc": "وصف قصير بالعربية.",
  "desc_de": "Kurze Beschreibung auf Deutsch.",
  "desc_en": "A short description in English.",
  "pushed": null,
  "added": "2026-10-25T09:30:00Z"
}
```

- `slug` هو الاسم بأحرف صغيرة وشرطات (نفس ما يُنتجه الاسم تلقائيًا).
- `cat` أحد أرقام الأقسام في `categories.json`، و`use` أرقام المشاريع في `projects.json`.
- `kind`: `Skill` أو `MCP` أو `مكتبة` أو `أداة` أو `تطبيق` أو `منصة` أو `موقع` (للمواقع التي تُستخدم من المتصفح، مثل أقسام مواقع الكتابة والبرومبت) أو `صيغة` (ملف بصيغة معيارية مثل DESIGN.md) أو `دليل` (قائمة تجمع أدوات أخرى). نوع جديد يحتاج ترجمته وأيقونته في `src/lib/data.ts`.
- شارة "جديد" تُحسب تلقائيًا من `added` (آخر 14 يومًا)، فلا حاجة لحقل `isNew`.
- اترك `stars` و`pushed` على `null`، فسكربت التحديث يملؤهما.
- `desc_de` و`desc_en` هما الوصف نفسه بالألمانية والإنجليزية للنسختين `/de/` و`/en/`. مطلوبان لكل أداة وبلا حروف عربية، و`npm run check` يرفض الأداة بدونهما.
- بعد الإضافة شغّل `npm run check` للتأكد أن كل شيء سليم.

## اللغات

الموقع بثلاث لغات: العربية في الجذر (`/`) والألمانية تحت `/de/` والإنجليزية تحت `/en/`، ولكل صفحة نسختها في اللغتين الأخريين، وقائمة اللغات في الشريط العلوي (وروابطها أيضًا في التذييل).

- نصوص الواجهة في `src/i18n/ui.ts` (وقت البناء) و`src/i18n/client.js` (السكربتات في المتصفح). أضف أي نص جديد باللغات الثلاث.
- نصوص البيانات: `desc_de` و`desc_en` لكل أداة في `data/tools.json`، و`name_de` و`name_en` لكل قسم في `data/categories.json`، و`name_*` و`advice_*` لكل مشروع في `data/projects.json`. اسم حقل كل لغة هو الحقل العربي الأصلي مع لاحقة اللغة.
- خريطة الموقع `sitemap.xml` تضم النسخ الثلاث مع روابط `hreflang`، ولكل لغة خلاصة RSS و`manifest`: `/feed.xml` و`/de/feed.xml` و`/en/feed.xml`.
- الصفحات الألمانية تخاطب القارئ بـ "du" كما في مواقع Apple الألمانية، والإنجليزية تخاطبه بـ "you" مباشرة بنبرة هادئة موجزة.

**لإضافة لغة رابعة** (مثل الفرنسية `fr`): أضفها إلى `Lang` و`LANGS` و`LANG_NAME` و`OG_LOCALE` في `src/i18n/index.ts`؛ ثم قاموسًا بالمفاتيح نفسها في `src/i18n/ui.ts` و`src/i18n/client.js`؛ ثم `KIND_L` و`INTL` و`BADGE` و`LANG_AR` في `src/lib/data.ts`؛ ثم `TR` في `scripts/check-data.mjs` وحقول `desc_fr` و`name_fr` و`advice_fr` في `data/`؛ ثم مجلد `src/pages/fr/` (انسخ `en/`)؛ وأخيرًا `home-fr.png` في `scripts/og-home.cjs` واللغة في `api/_feedback.js` و`scripts/check-brand.mjs`. إن كانت لغة تُكتب من اليمين فعدّل أيضًا `dirOf` و`fwdIcon`.

## البحث والتثبيت

- **البحث الذكي** (`src/lib/search.js`): نفس التطبيع للنص وللكلمة المكتوبة، فتتطابق «أيقونة» و«ايقونه» و«إيقونات»، و«Größe» و«grosse»، والأرقام العربية واللاتينية.
  - تُحذف «ال» وأخواتها وعلامات الجمع، فيجد «التطبيقات» نصًا فيه «تطبيق».
  - الأسماء التقنية المكتوبة بحروف عربية تُفهم: «فيجما» وFigma، و«شوبيفاي» وShopify، و«بي دي اف» وPDF. القائمة في `TRANSLIT` داخل الملف نفسه؛ أضف إليها ما يكتبه الزوار.
  - النتائج مرتبة حسب القرب: الاسم أولًا، ثم النوع والقسم، ثم الوصف. ويظهر «هل تقصد» عند خطأ إملائي («shopfy» → shopify).
- **البحث بكل اللغات:** فهرس `/search.json` (و`/de/` و`/en/`) يُبنى من `src/lib/search-index.ts` فيه أوصاف الأدوات باللغات الثلاث، فيجد الزائر «invoice» في الصفحة العربية و«فاتورة» في الألمانية. يُحمَّل عند أول اقتراب من البحث فقط (حوالي 60KB مضغوطًا).
- **الرابط يحفظ العرض:** البحث والقسم والمشروع والترتيب في رابط الصفحة (`/?q=seo&cat=writing`)، فيُشارَك كما هو. زر «مشاركة هذه النتائج» في شريط الفلاتر النشطة. الروابط القديمة بالمشروع (`/#shop`) ما زالت تعمل.
- **البحث السريع:** في صفحات الأدوات والمفضلة و404 زر بحث في الشريط العلوي، ويُفتح أيضًا بـ `Ctrl/⌘+K` أو `/`. الأسهم للتنقل وEnter للفتح، و«كل النتائج» يفتح الرئيسية مفلترة بالبحث نفسه.
- **حزمة التثبيت:** زر في المفضلة وفي «ابدأ بهذه» لكل مشروع، يجمع أوامر عدة أدوات في نص واحد للطرفية.
  - تدخل الحزمة أوامر إضافات Claude Code والأدوات العامة فقط (`claude mcp add` و`claude plugin` و`npx skills add` و`npm install -g` و`brew install`)، و`/plugin` تتحول إلى `claude plugin` لأن أوامر الشرطة المائلة لا تعمل خارج جلسة Claude Code.
  - لا تدخلها: السكربتات من الإنترنت، والأوامر التي تحتاج قيمك، ومكتبات المشروع. تظهر في النافذة بسبب كل منها ورابط صفحتها.
  - القواعد في `kitPlan` داخل `src/lib/install.js`.
- **الفحص:** `npm run check-search` (ويعمل في CI) يختبر التطبيع والترتيب و«هل تقصد» وقراءة أوامر `claude mcp add` وقواعد الحزمة على كل الأدوات. شغّله بعد أي تعديل على `src/lib/search.js` أو `src/lib/install.js`.
- **خوادم MCP في برامج أخرى:** إن كان أمر الأداة `claude mcp add …` (أو `npx mcp-remote <رابط>`) فصفحتها فيها تبويبات لـ Cursor وVS Code (رابط تثبيت بنقرة وملف الإعداد) وClaude Desktop (ملف الإعداد، أو موصل مخصص للخادم البعيد). تُستخرج من الأمر في `mcpServer` داخل `src/lib/install.js`، فلا حقول إضافية في البيانات.

## الأمان والثقة وصفحات الأقسام

- **الأمان والثقة** في صفحة كل أداة (`src/lib/trust.ts`): ثلاث إشارات من البيانات نفسها بلا درجات مخترعة، ثم نصيحة واحدة قبل التثبيت تناسب نوع الأداة:
  - **الناشر:** الحساب الرسمي للجهة (من قائمة `OFFICIAL` لحسابات GitHub الرسمية)، أو اسم الحساب فقط، أو الموقع الرسمي للأدوات التي بلا مستودع. أضف إلى `OFFICIAL` حين تضيف أداة من حساب رسمي لجهة معروفة.
  - **أين تعمل:** على جهازك، أو خادم بعيد مع اسم من يستقبل البيانات، أو داخل Claude، أو إضافة لـ Claude Code (قد تضم hooks)، أو داخل كود مشروعك.
  - **من أين تُثبَّت:** سوق Anthropic الرسمي، أو سوق في مستودع، أو مستودع GitHub، أو حزمة npm وPyPI وHomebrew وpub.dev مع رابط صفحتها، أو تحذير من سكربت الإنترنت.
- **صفحات الأقسام** `/category/<id>/` (ومثلها `/de/` و`/en/`): كل أدوات القسم مرتبة بالنجوم، مع بيانات منظمة (`ItemList` و`BreadcrumbList`) وروابط الأقسام الأخرى. موجودة في `sitemap.xml`، ويشير إليها مسار صفحة الأداة والبحث السريع وصفحة 404.

## المقارنة

- **صفحة المقارنة** `/compare/?t=a,b,c` (ومثلها `/de/` و`/en/`): حتى ثلاث أدوات جنبًا إلى جنب، بالقسم والنجوم والوصف والناشر وأين تعمل ومصدر التثبيت والرخصة وآخر تحديث وطرق التثبيت وأمر التثبيت.
  - البيانات من `/compare.json` (`src/lib/compare-index.ts`)، والجدول يبنيه `src/scripts/compare.js`. الرابط يتبع الاختيار فيُشارَك.
  - الصفحة غير مفهرسة (`noindex`) لأن محتواها يتغير مع الرابط.
- **المداخل:** زر «قارن» في صفحة كل أداة (يفتح المقارنة معها ومع أقرب أداة من قسمها)، ورابط «قارن بين هذه الأدوات» تحت الأدوات المشابهة، وزر «قارن» في المفضلة (أحدث ثلاث).
- **المقارنات المقترحة** تظهر حين لا تختار أدوات: قائمة يدوية في `SUGGESTED` داخل `src/lib/compare-index.ts` لأدوات تحل المشكلة نفسها.

## تحديث النجوم تلقائيًا

ملف `.github/workflows/update-stars.yml` يعمل كل يوم اثنين، ويجلب النجوم وتاريخ آخر تحديث من GitHub، ثم يحفظ التغييرات في المستودع. كل تغيير يعيد نشر الموقع تلقائيًا على Vercel.

- للتشغيل اليدوي: تبويب **Actions** ثم **Update GitHub stars** ثم **Run workflow**.
- محليًا: `npm run update-stars`. يعمل بدون توكن لكن بحد 60 طلبًا في الساعة، فاستخدم `GITHUB_TOKEN=ghp_xxx npm run update-stars`.
- أي مستودع يفشل جلبه يبقى رقمه القديم، ولا يتوقف التحديث بسببه.

## اكتشاف أدوات جديدة تلقائيًا

ملف `.github/workflows/discover-tools.yml` يعمل كل يوم اثنين، ويبحث في GitHub عن مستودعات جديدة بموضوعات مثل `claude-skills` و`mcp-server` و`agent-skills`، بشرط حد أدنى من النجوم ونشاط حديث. ثم يفتح **Issue** فيه المرشحون الجدد مع:

- الوصف الأصلي، والنجوم، والرخصة، وآخر تحديث.
- تحذيرات: بدون رخصة، رخصة AGPL، مستودع حديث جدًا بنجوم كثيرة، مهارة قد تنفّذ أوامر.
- كتلة JSON جاهزة للنسخ إلى `data/tools.json`.

لا يُضاف شيء إلى الموقع تلقائيًا. للموافقة على مرشح: انسخ كتلته وأكمل `desc` بالعربية و`desc_de` بالألمانية و`desc_en` بالإنجليزية و`cmd` و`use`، ثم `npm run check`. ولإخفاء مرشح تلقائيًا في المرات القادمة، أضف اسمه (مثل `owner/repo`) إلى `ignored` في `data/discover-state.json`.

- الإعدادات (المواضيع، الحد الأدنى للنجوم، عدد المرشحين): `data/discover.config.json`.
- تجربة محلية دون حفظ حالة: `GITHUB_TOKEN=ghp_xxx npm run discover`، فيكتب `candidates-report.md`.
- المرشحون الذين عُرضوا مرة لا يظهرون ثانية (محفوظون في `data/discover-state.json`).

## الإشعارات والإخفاء والحذف

- **جرس الإشعارات:** أيقونة في أعلى الصفحة تعرض عدد الأدوات المضافة منذ آخر مرة قرأ فيها الزائر الإشعارات. الحساب يتم داخل متصفح الزائر بحقل `added` في كل أداة، فلا يحتاج الموقع إلى حسابات أو خادم. في أول زيارة لا يظهر شيء، ويبدأ العدّ من تلك اللحظة.
- **المفضلة:** قلب على كل أداة (في الصفحة الرئيسية وصفحة الأداة). الضغط عليه يحفظ الأداة في صفحة `/favorites`، وأيقونة القلب في أعلى الصفحة تفتحها وتعرض العدد. تُحفظ في متصفح الزائر فقط وتتزامن بين تبويبات المتصفح المفتوحة. صفحة المفضلة غير مفهرسة في محركات البحث.
  - **مشاركة القائمة:** زر «مشاركة القائمة» يصنع رابطًا `/favorites/?list=a,b,c` (60 أداة بحد أقصى). من يفتحه يرى القائمة نفسها، ويضيفها كلها إلى مفضلته بزر، أو يثبّتها حزمة واحدة. لا شيء يُرسل إلى خادم: القائمة في الرابط نفسه.
- **تاريخ الإضافة:** على كل بطاقة وصفحة أداة شارة حديثة تعرض متى أُضيفت الأداة إلى الدليل (اليوم، أمس، قبل 3 أيام...). يظهر التاريخ الكامل عند التمرير، ونقطة نابضة للأدوات المضافة قبل 3 أيام أو أقل. الحقل `added` في `data/tools.json` بصيغة `YYYY-MM-DDTHH:MM:SSZ`. الأدوات الأولى كلها بتاريخ 24 أكتوبر 2026.
- **الأحدث إضافةً:** خيار في قائمة الترتيب يعرض الأدوات من الأحدث إلى الأقدم حسب `added`.
- **التصنيف بالنجوم:** داخل كل قسم تظهر الأدوات من الأعلى نجومًا إلى الأقل. وخيار "تصنيف عام" في قائمة الترتيب يعرض كل الأدوات في قائمة واحدة برقم لكل أداة (#1 و#2 ...). الأدوات التي بلا نجوم تأتي في النهاية بدون رقم. عند اختيار نوع مشروع أو بحث يبدأ الترقيم من جديد بين النتائج المعروضة.
- **شارات الحالة:** يجلب سكربت النجوم أيضًا رخصة كل مستودع وحالة الأرشفة وتاريخ آخر تحديث، فتظهر على البطاقة شارات: رخصة (مثل MIT)، وتنبيه (آخر تحديث قبل أكثر من سنة، أو رخصة بشروط مثل AGPL)، وخطر (مؤرشف أو بلا رخصة). تظهر الشارات بعد أول تشغيل لسكربت التحديث.
- **خلاصة RSS:** الرابط `/feed.xml` (و`/de/feed.xml` بالألمانية و`/en/feed.xml` بالإنجليزية) فيه آخر 30 أداة مضافة، ويمكن الاشتراك فيه من أي قارئ RSS.
- **إخفاء أداة:** زر العين على كل بطاقة يخفيها من عرض الزائر فقط، ويحفظ ذلك في متصفحه، مع زر "استعادة المخفية". لا يغيّر الموقع للآخرين.
- **حذف نهائي:** `npm run remove -- <slug>` يحذف الأداة من `data/tools.json` ومن اقتراحات المشاريع، ويضيفها إلى قائمة `ignored` حتى لا يعيد البحث التلقائي اقتراحها. بعده شغّل `npm run check` ثم ارفع التغيير.
- **أداة جديدة:** عند إضافتها اكتب في `added` وقتها بصيغة `2026-10-25T09:30:00Z`، فتظهر في الجرس عند الزوار.

## فحص الروابط أسبوعيًا

ملف `.github/workflows/check-links.yml` يعمل كل يوم اثنين الساعة 07:11 UTC، ويفحص كل روابط `GitHub` والمواقع الرسمية في `data/tools.json`، ثم يفتح **Issue** (أو يضيف تعليقًا على الموجود) بعنوان "روابط معطلة أو منقولة في الدليل" إذا وجد مشكلة. لا يفتح شيئًا إن كانت كل الروابط سليمة، ولا يغيّر أي ملف.

- **معطّلة:** الصفحة غير موجودة (404 أو 410) أو النطاق لا يعمل. صحّح الرابط أو احذف الأداة بـ `npm run remove -- slug`.
- **منقولة:** الرابط يحوّل إلى مستودع أو نطاق آخر. حدّثه.
- **غير مؤكدة:** مهلة أو حجب للفاحص الآلي (403 و429). تظهر في قسم مطوي، ولا تُعد معطّلة حتى لا تصلك إنذارات كاذبة.
- إذا فشل أكثر من نصف الروابط فالفاحص يعتبر أن المشكلة في الاتصال ولا يكتب تقريرًا.
- تجربة محلية: `npm run check-links`، ويكتب `links-report.md`.

## رأي الزوار

بعد دقيقة من التصفح الفعلي تظهر على يمين الشاشة نافذة تسأل الزائر عن رأيه في الدليل: تقييم من 1 إلى 5 نجوم ورسالة اختيارية. تظهر مرة واحدة فقط، وإن أغلقها الزائر لا تعود قبل 30 يومًا، وإن أرسل رأيه لا تعود أبدًا. ويمكن فتحها في أي وقت من رابط "رأيك في الدليل" في التذييل.

- النافذة: `src/components/Feedback.astro` و`src/scripts/feedback.js`.
- الاستقبال: دالة Vercel في `api/feedback.js` تتحقق من البيانات (`api/_feedback.js`) وتحفظ كل رأي كملف JSON في مخزن Vercel Blob الخاص `xskills-feedback`.
- **لقراءة الآراء:** لوحة Vercel ثم **Storage** ثم `xskills-feedback` ثم **Browser**، والملفات في مجلد `feedback/` مرتبة حسب التاريخ.
- لا يُحفظ اسم ولا بريد ولا عنوان IP: التقييم والرسالة واللغة والصفحة ووقت الإرسال فقط.
- المتغير `BLOB_READ_WRITE_TOKEN` يضيفه Vercel تلقائيًا لأن المخزن مربوط بالمشروع. بدونه ترد الدالة بخطأ 503 وتعرض النافذة "تعذّر الإرسال".
- **الإبلاغ عن مشكلة في أداة:** رابط «هل لاحظت مشكلة؟» تحت مواصفات كل أداة يفتح نافذة بسبب من قائمة ثابتة (رابط لا يعمل، أمر لا يعمل، معلومات قديمة، أمان، غير ذلك) ورسالة اختيارية. تصل إلى الدالة نفسها بـ `kind: "report"` وتُحفظ في مجلد `reports/` في المخزن نفسه، ومعها اسم الأداة (`slug`). النافذة في `src/components/ReportDialog.astro` و`src/scripts/report.js`، والتحقق في `parseReport` داخل `api/_feedback.js`.

## الشعار والأيقونات

رسم الشعار في مكان واحد هو `src/lib/brand.js`، وتستخدمه الواجهة وصور المشاركة ومجموعة الأيقونات، فلا ينسخ أحد SVG الشعار إلى ملف آخر.

- **التوليد:** `npm run brand` يكتب في `public/`: `favicon.svg` و`favicon.ico` (16 و32 و48) و`apple-touch-icon.png` (180) و`icon-192.png` و`icon-512.png` و`icon-maskable-512.png` و`logo.svg`، وفي `public/brand/`: `avatar-1024.png` (صورة الحساب على المنصات) و`logo-1024.png` و`logo-mono.svg` (لون واحد للأختام). ارفع الملفات الناتجة مع التعديل.
- **التحقق:** `npm run check-brand` بعد البناء (ويعمل في CI): الملفات موجودة بأحجامها، ووسوم `<head>` تشير إلى ملفات موجودة، وأيقونات manifest بأحجامها المعلنة.
- **manifest** لكل لغة من `src/lib/manifest.ts` (`/manifest.webmanifest` و`/de/manifest.webmanifest` و`/en/manifest.webmanifest`): يقرؤه أندرويد وChrome عند "إضافة إلى الشاشة الرئيسية".
- **لماذا ملفات حقيقية وليس رابط data-URI؟** Safari على iPhone وزاحف أيقونات Google لا يقرآن أيقونة مضمّنة في الصفحة، ويطلبان `/favicon.ico` و`apple-touch-icon`.

## النشر على Vercel

1. افتح `vercel.com/new` واستورد المستودع.
2. في **Framework Preset** اختر **Astro**. الباقي يُترك كما هو.
3. بعد النشر، ربط دومين خاص من **Settings ثم Domains**.

الرابط العام يُؤخذ تلقائيًا لخريطة الموقع `sitemap.xml`. وإن أردت تحديده يدويًا فأضف متغير البيئة `SITE_URL` في Vercel.

`vercel.json` يضيف ترويسات فقط، ولا يغيّر إعدادات البناء:
- ملفات `/_astro/` (أسماؤها تتغير مع كل تعديل) تُحفظ في متصفح الزائر سنة كاملة (`immutable`)، فلا يعيد طلبها في الزيارة التالية.
- ترويسات أمان لكل الصفحات: `X-Content-Type-Options` و`Referrer-Policy` و`X-Frame-Options: SAMEORIGIN` (لا تُعرض الصفحات داخل إطار في موقع آخر) و`Permissions-Policy` (لا كاميرا ولا ميكروفون ولا موقع).
